# Kind File Shapes

Reference examples for all 7 MCP kind files generated by the rest-to-mcp-generator skill.

For **MCPTools and MCPServer** the schema is fixed and built directly — no CLI needed.
For **Invoke, Telemetry, Quota, and FreeFlowPolicySequence** always retrieve the live schema via `apic schema get <Kind> --gateway lwgw` first.

---

## MCPTools

The example below illustrates every field discussed in Step 3, using the Petstore spec as a reference:

```yaml
kind: MCPTools
apiVersion: api.ibm.com/v1
metadata:
  name: pet-store-mcp-tool-ab3f9
  namespace: my-project
  version: 1.0
  tags: []
  description: "A sample Pet Store API"
spec:
  tools:
    # operationId present; description takes priority over summary
    - name: deletePet
      title: "Deletes a pet"                  # from summary — only when summary exists
      description: "Delete a pet by ID"       # from description (preferred over summary)
      inputSchema:
        type: object
        properties:
          petId:
            type: integer
            format: int64
            description: "Pet id to delete"
            example: 10
            x-parameter-location: path        # ALWAYS on URL parameters
          api_key:
            type: string
            description: "API key for authentication"
            x-parameter-location: header      # synthesised from apiKey-in-header securityScheme
        required:
          - petId
      x-api-binding:
        operationPath: /pet/{petId}
        operationMethod: DELETE
        api:
          $path: ./pet-store-spec.yml

    # enum + example on query param
    - name: findPetsByStatus
      title: "Finds Pets by status"
      description: "Multiple status values can be provided with comma separated strings"
      inputSchema:
        type: object
        properties:
          status:
            type: string
            description: "Status values that need to be considered for filter"
            enum:
              - available
              - pending
              - sold
            example: available
            x-parameter-location: query
      x-api-binding:
        operationPath: /pet/findByStatus
        operationMethod: GET
        api:
          $path: ./pet-store-spec.yml

    # request body with nested category object, array photoUrls, quantity
    - name: addPet
      title: "Add a new pet to the store"
      description: "Add a new pet to the store"
      inputSchema:
        type: object
        properties:
          name:
            type: string
            description: "Name of the pet"
            example: doggie
          photoUrls:
            type: array                        # items MUST be present for array types
            items:
              type: string
            description: "Photo URLs of the pet"
          status:
            type: string
            description: "Pet status in store"
            enum:
              - available
              - pending
              - sold
          category:
            type: object                       # inlined from $ref Category
            properties:
              id:
                type: integer
                format: int64
                example: 1
              name:
                type: string
                example: Dogs
            description: "Category of the pet"
          quantity:
            type: integer
            format: int32
            description: "Number of items in stock"
            example: 7
        required:
          - name
          - photoUrls
      x-api-binding:
        operationPath: /pet
        operationMethod: POST
        api:
          $path: ./pet-store-spec.yml

    # no operationId — name from method + last path segment (underscore separator)
    - name: post_order
      title: "Place an order for a pet"
      description: "Place a new order in the store"
      inputSchema:
        type: object
        properties:
          petId:
            type: integer
            format: int64
            description: "Pet ID"
            example: 198772
          quantity:
            type: integer
            format: int32
            description: "Quantity ordered"
            example: 7
          status:
            type: string
            description: "Order status"
            enum:
              - placed
              - approved
              - delivered
            example: approved
        required:
          - petId
      x-api-binding:
        operationPath: /store/order
        operationMethod: POST
        api:
          $path: ./pet-store-spec.yml
```

## MCPServer

```yaml
kind: MCPServer
apiVersion: api.ibm.com/v1
metadata:
  name: pet-store-mcp-server-ab3f9
  namespace: my-project
  version: 1.0
  tags: []
spec:
  title: Pet Store MCP Server
  protocolVersion: V2025_11_25
  policy-sequence:
    - $ref: my-project:my-project-freeflowpolicysequence-ab3f9:1.0
  capabilities:
    tools:
      - $ref: my-project:pet-store-mcp-tool-ab3f9:1.0
  quota:
    $ref: my-project:my-project-quota-ab3f9:1.0
```

## Invoke

```yaml
kind: Invoke
apiVersion: api.ibm.com/v1
metadata:
  name: invoke-ab3f9
  namespace: my-project
  version: 1.0
  tags: []
  labels:
    gatewayTypes: [nano]
spec:
  endpoint:
    http:
      target:
        tlsClientProfile: tls-client-profile-default:1.0.0
        url: "'https://backend.example.com' & $pathAndQuery()"
        urlType: jsonata
        persistentConnections: false
        timeout: 30
        decompressResponse: true
        followRedirects: false
        chunkedUpload: false
```

## Quota

```yaml
kind: Quota
apiVersion: api.ibm.com/v1
metadata:
  name: my-project-quota-ab3f9
  namespace: my-project
  version: 1.0
  tags: []
spec:
  maxRequest: 1000
  interval: 1m
  extensions:
    dp-nano-gateway:
      apiVersion: api.ibm.com/v1
      spec:
        exceedAction: return429
```
